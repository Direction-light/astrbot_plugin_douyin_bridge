# 抖音日报桥 · astrbot_plugin_douyin_bridge

把本地生成的「抖音值班报告」里**值得看**的条目，按你给的人设转述成一两条口语消息，定时私聊推送到 QQ。

它只做三件事：**读本地 Markdown → 交给你配的模型转述 → 发到指定会话**。不抓抖音、不带登录态、不联网取数据。

> 典型场景：本机有个东西每天刷抖音、把值得看的写成一份 `2026-11-01.md`；
> 这个插件负责在合适的时间把它变成"人话"，私聊发给你关心的人。
> 深夜不发，早上连同昨晚没发完的一起补上。

## 前置条件

**这个插件单独用不起来**，它需要有人往一个目录里写报告。你需要：

1. AstrBot 4.x（本插件在 4.29 上跑过）
2. 一个能产出下述格式报告的「上游」——本作者的搭配是本地跑的一个抖音值班流程，但它不是本仓库的一部分，也不在依赖里
3. 一台能访问你 AstrBot 所在文件的机器（插件直接读本地文件）

报告格式很简单，任何脚本都能按它写。见下一节。

## 报告格式

目录里一天一个文件，文件名必须是 `YYYY-MM-DD.md`：

```
# 刷抖音 · 2026-11-01（第 3 轮 22:14）

> ⏰ 本轮时间：2026-11-01 22:14（北京时间）

## 值得看

### 7000000000000000001
**标题** · @作者甲 · 20 秒 · 约 3 小时前
🔗 https://www.douyin.com/video/7000000000000000001
📊 赞 100 · 评 10 · 藏 20｜评/赞 0.10
**为什么值得**：……
**一句话**：……

### 7000000000000000002
**另一条** · @作者乙 · 12 秒
🔗 https://www.douyin.com/video/7000000000000000002
```

解析规则：

| 规则 | 说明 |
|---|---|
| 只认 `## 值得看` 段 | 其他段（如「顺带一提」「没把握」）全部忽略 |
| `### <纯数字ID>` 是条目边界 | 一行一个条目，ID 至少 6 位数字 |
| 同一天可能有多轮 | 报告按轮次追加进同一个文件；同一个 ID 只取**第一次**出现的完整块 |
| 其余字段都可选 | `🔗` 链接、`📊` 数据、`**为什么值得**`、`**一句话**`，缺了不影响 |

字段提取出来后交给模型时，只用到：标题、作者、为什么值得、一句话、链接。

## 安装

```bash
cd /path/to/astrbot/data/plugins
git clone https://github.com/Direction-light/astrbot_plugin_douyin_bridge.git
```

然后在 AstrBot 面板里重载插件（或重启）。日志里出现这一行就是起来了：

```
[douyin-bridge] 已启动｜报告目录=…｜静默=23:00-09:00｜回看=1天｜目标=…
```

**先别急着开 `auto_send`**：把 `auto_send` 关掉跑一轮，去日志里看模型生成的措辞对不对，再打开真发。

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `target_umo` | 空 | **必填**。发到哪个会话，格式 `平台:FriendMessage:QQ号`。空着插件一条都不会发 |
| `extra_umos` | `[]` | 额外目标，各自独立收到每一行消息 |
| `quiet_hours` | `23:00-09:00` | 静默时段，只存不发。留空 = 从不静默。支持跨午夜区间 |
| `report_dir` | 空 | 报告目录。空 = `$DSH_HOME/douyin-duty/out` |
| `lookback_days` | `1` | 往前看几天。`1` = 昨天+今天（**跨午夜补发靠它**）；`0` = 只看今天；上限 7 |
| `poll_seconds` | `600` | 多久检查一次报告，最小 60 |
| `max_items` | `3` | 一次最多聊几条，剩下的下一轮继续 |
| `auto_send` | `true` | 关掉就只生成不发送，生成结果写日志 |
| `chat_provider_id` | 空 | 用哪个对话模型，空 = 当前默认 |
| `persona_path` | 空 | 人设 txt 路径（UTF-8） |
| `persona_text` | 空 | 人设正文，面板里直接粘贴 |

人设是**三层降级**：`persona_path` 读得到就用它 → 否则用 `persona_text` → 两个都没有才用中性兜底。
「抖音日报状态」会告诉你这一轮用的是哪一层，路径写错了不会一声不响地换语气。

## 静默与补发

这是本插件最容易搞错的地方：报告是**一天一个文件**，而静默时段**跨了午夜**。

所以 `23:00` 之后判断出来的值得看条目，躺在 `11-01.md` 里；到了次日 `09:00`，
如果只读「今天」的那份（`11-02.md`），它们就永远发不出去了 —— 过了 00:00，它已经不叫今天了。

于是发送窗口默认是 **昨天 + 今天**：

- 静默时段内：`_tick` 直接返回，一条不发
- 静默结束后的第一轮：把两天的报告合并、按 ID 去重（**保留较早那份的说法**）、再过滤掉已发的
- 一次最多 `max_items` 条，剩下的下一轮（`poll_seconds`）继续发 —— 不会一股脑砸过去

延迟上限：静默结束到实际发出，最多晚一个 `poll_seconds`。

## 去重

已发送记录在插件数据目录的 `sent.json`，键是 `视频ID@本轮时间`：

- 同一条视频**同一天同一次推荐**不会发两遍
- 同一条视频被**不同轮次**推荐，会发两遍 —— 那是两次独立推荐，算新内容
- 记录保留 30 天，自动清理

## 指令

| 指令 | 权限 | 作用 |
|---|---|---|
| `抖音日报状态` | 所有人 | 读取窗口、值得看几条、几条没发、当前是否静默、报告目录、人设来源、发送目标 |
| `抖音日报推送` | 管理员 | 立刻推一轮（忽略静默时段） |

## 隐私

- 插件**不采集、不上传**任何东西。它只读 `report_dir` 下的 Markdown，只往 `sent.json` 写发送记录。
- 报告和人设都在你自己的机器上；转述用的模型由你自己的 AstrBot provider 决定 —— 报告内容会作为提示词发给那个模型。
- 本仓库**不含任何账号、Cookie、密钥、人设文本或发送目标**。`target_umo`、人设、目录全部由你在面板里填。

## 开发

纯标准库，无第三方依赖；测试要 pytest。

```bash
python -m pytest -q
```

`main.py` 只做接线（读配置、起定时器、调 AstrBot 发送），所有判断逻辑在 `core/` 里，且都有测试：

| 模块 | 负责 |
|---|---|
| `core/clock.py` | 静默时段判定、发送窗口（`report_days`） |
| `core/report.py` | 解析 Markdown、跨天合并去重（`merge_reports` / `read_reports`） |
| `core/persona.py` | 人设三层降级（`resolve_persona`） |
| `core/compose.py` | 拼提示词、切消息 |
| `core/sentlog.py` | 已发送记录 |

## 已知限制

- 只发文本，不发图片/视频/分享卡片
- 报告必须是上述 Markdown 格式，没有自动适配别的格式
- 指令名是中文的，英文用户需要改 `main.py` 里的 `@filter.command(...)`
- 没在 AstrBot 4.29 以外的版本上验证过
